# Melos discovery routes

## User request

Retain the existing painting hero and add three large rectangular entry points
immediately below it: Explore lexicon, Explore authors, Explore themes.
Keep Melos's white, dark-blue, serif, square frosted-glass visual language.

## Deliverables

- Dedicated lexicon route: Greek headword browsing, Greek/forms/transliteration
  and English lookup, short sourced meanings, distinct candidate parsings,
  full source entries and links to the existing contextual reader and usages.
- Dedicated author route: expand the preserved vertical chronology/floruit
  design, retain uncertainty and source provenance, improve portrait crops and
  selections, and link authors to their actual works and passages.
- Expanded author profiles: place a sourced biography beneath the enlarged
  portrait, with Wikipedia revision/license attribution and separately cited
  online commentary excerpts where available. Do not fill missing biographies
  or historical likenesses from model memory.
- Dedicated themes route, opening in a new tab from the home entry: vertical
  artwork-backed nature categories plus literary discovery prompts (love,
  politics, sympotic song, and related categories). Search results must
  distinguish existing aesthetic annotations from semantic retrieval.
- Search granularity: inspect and extend the backend so supported passage,
  stanza, line, sentence, phrase and word units retain parent links and exact
  source spans. Do not claim independent hierarchical embeddings where only
  parent embeddings exist. Unsupported units must not silently impersonate
  whole-poem matches. Keep a path to materialised hierarchical indexes.
- Reuse compressed nature presets and delay nonessential image requests;
  retain portrait originals and all saved favourites.

## Integrity and scope

No invented headwords, senses, dates, source quotations, poem boundaries or
literary classifications. Source-derived evidence remains separate from model
ranking and aesthetic choices. No implication of TLG coverage or accuracy
parity without an appropriate benchmark. Existing API/provider budgets remain.
Preserve unrelated working-tree changes and existing deployment rollback.

## Verification and delivery

Use bounded parallel agents with distinct file ownership. Test routes,
search/form behaviour, URL state, empty/error states, source provenance,
safe rendering, responsive layouts and navigation. Inspect the design with
computer use. Publish the finished, verified routes to the live Vercel site;
deploy backend additions to the existing Hetzner service only with scoped
verification and rollback. Report implemented capabilities and real limits.
